## Remote Control의 역할

Remote Control은 Claude Code의 로컬 세션을 다른 기기에서 이어서 제어하는 연구 미리보기(research preview) 기능이다. 세션이 실행되는 컴퓨터에 새 원격 실행 환경을 만들거나 파일을 Claude 서버로 옮기는 기능이 아니다. 파일 시스템, MCP 서버, 도구, 설정은 계속 **로컬 컴퓨터**에서 사용되며, 원격 기기는 제어 인터페이스 역할을 한다.

~~~text
원격 기기 (브라우저·모바일)
           │ 세션 제어
           ▼
로컬 Claude Code 세션 ── 파일·셸·MCP ── 로컬 작업공간
           │
           └──────────── 모델 서비스
~~~

따라서 원격에서 명령을 승인하기 전에, 그 명령이 실제로는 로컬 저장소와 자격 증명을 가진 환경에서 실행된다는 점을 확인해야 한다. 작업공간 신뢰와 권한 설정을 평소보다 더 보수적으로 유지하는 이유다.

## 공식 진입점과 사전 조건

공식 문서에는 대화형 세션에서 /remote-control(또는 /rc)을 사용하거나, 다음 CLI 흐름이 안내되어 있다.

~~~bash
# 현재 프로젝트에서 원격 제어 세션 시작
claude --remote-control "프로젝트 작업"

# 여러 원격 세션을 받을 서버 모드
claude remote-control
~~~

Remote Control은 최소 지원 버전, Claude.ai 로그인, 작업공간 신뢰가 필요하며 Team·Enterprise에서는 관리자가 사용을 제어할 수 있다. 정확한 버전 요구와 플래그는 바뀔 수 있으므로 사용 직전에 공식 문서와 claude --help를 확인한다. 문서에 없는 환경 변수, 예약 트리거, 음성·백그라운드 플래그를 Claude Code 설정이나 실행 방법으로 사용하면 안 된다.

## 세션을 나누는 방법

서버 모드에서는 같은 디렉터리, worktree, 기존 세션 등 시작 방식을 선택할 수 있다. 같은 파일을 편집하는 병렬 세션은 충돌할 수 있으므로, 기능별 파일 경계를 나누거나 worktree를 선택해 격리한다.

| 방식 | 적합한 경우 | 주의점 |
| --- | --- | --- |
| 같은 디렉터리 | 한 작업을 다른 기기에서 이어서 처리 | 동시에 쓰면 충돌 가능 |
| worktree | 독립적인 수정·검토를 병렬 수행 | 병합과 테스트는 별도로 수행 |
| 기존 세션 | 이미 축적한 대화 맥락을 계속 사용 | 세션 기록은 파일 변경 자체를 되돌리지 않는다 |

## 자동화와의 경계

Remote Control은 사람이 원격으로 **세션을 조작**하는 기능이다. 정기 실행, 메일 알림, 배포 판단을 선언하는 예약 트리거 구성은 공개 Claude Code 기능이 아니다. 예약 작업이 필요하다면 조직이 운영하는 CI 또는 스케줄러에 별도로 인증·비밀 관리·승인 절차를 구성하고, Claude Code의 비대화형 사용은 그 환경의 최소 권한과 로그 정책 안에서 검토해야 한다.

이 구분은 특히 중요하다. 원격 제어는 편의 기능이고, 무인 자동화는 실행 주체·권한·감사·실패 복구를 따로 설계해야 하는 운영 시스템이기 때문이다.
